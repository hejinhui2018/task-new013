# 联合改稿工作台

面向公关团队的三方联合改稿工具：品牌与法务在同一份底稿上各自修改后，系统按段落做三方合并，自动吸收互不冲突的修改，把真正需要人决定的冲突逐条呈现出来处理。所有数据仅保存在浏览器本地（localStorage），不经过任何服务器。

技术栈：React 18 + TypeScript + Vite，测试用 Vitest + Testing Library。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 开发模式（默认 http://localhost:5173）
npm test           # 运行全部测试（80 个用例）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 本地预览生产构建
```

## 功能

- **四栏并排**：共同底稿 / 品牌版 / 法务版 / 合并结果，逐段对照。
- **三方段落合并**（`src/lib/merge.ts`）：
  - 只有一方修改（或双方改得一样）→ 自动采用；
  - 双方改了同一段且结果不同 → `edit-edit` 冲突；
  - 一方删除、另一方修改 → `delete-edit` 冲突；一方删除、另一方移动 → `delete-move` 冲突；
  - 双方把同一段移到不同位置 → `move-move` 冲突；
  - **一方移动、另一方只改内容 → 自动合并：保留新位置，同时采用新内容**，不会误判成"删除 + 新增"。
- **移动识别**（`src/lib/align.ts`）：LCS 锚点 + 词级相似度贪心配对 + 最长递增子序列（LIS）判定相对顺序，被移动的段落带 `⇄ 移动` 徽章并标注来源位置。
- **冲突处理**：工具栏/左侧列表逐个跳转冲突；每处冲突可选 **采用品牌版 / 采用法务版 / 保留底稿 / 手动填写**；已解决的可以"重新打开"。
- **撤销 / 重做**：`Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`（或 `Ctrl+Y`），覆盖所有裁决操作与"恢复示例"。
- **一键恢复示例**：内置一份联合发布稿，覆盖互不冲突修改、同段冲突、删除与编辑冲突、双方插入、段落移动+改写等全部场景。
- **可编辑原稿**：三栏原稿均可直接编辑（空行分段），保存后立即重新合并。
- **可读性**：段落内做词级 diff（中文按字、英文按词），删除用删除线、新增用下划线，配合图标+文字徽章，不依赖颜色传达信息；点击合并结果中的段落可在两侧原稿中高亮定位。
- **导出**：一键复制 / 下载合并稿（未解决冲突会以标记行注明并暂留底稿原文）。批注仅存在于界面与本地数据中，**绝不会混入复制 / 下载的正文**。

## 批注（锚点评论）

审稿人在合并结果里**选中文字即可留言**，右侧"批注"栏列出全部批注并可**一键跳回原文**。批注不依赖易变的段落位置，而靠"稳定块身份 + 引文与前后缀指纹"在每次重新合并后自动重判落点（`src/lib/annotation.ts`）：

- **段落移动 / 只改一侧 / 重新合并** → 批注跟随同一段落；原文有小幅措辞变化时按词级相似度模糊跟随（低于阈值不跟）。
- **目标被删除或大幅重写** → 明确标为 `待重挂`，不猜测位置。
- **出现多个相同候选**（如同段出现两次相同短句且指纹无法区分）→ 标为 `位置有歧义`，列出全部候选供点选，不自动选用。
- **落入未解决冲突** → 标为 `待冲突解决`，不挂在临时文本上；**冲突一解决立即自动重新判断**（恢复挂接或转为待重挂）。
- 上述任何异常状态都可以**手动重挂**：点"手动重挂"后在正文选中新文字确认；歧义状态也可直接点候选。
- 批注的**新增 / 编辑 / 删除 / 重挂**与冲突裁决共用同一条撤销重做栈，并持久化到 localStorage（刷新恢复）。旧版数据（无批注字段）可直接打开，批注按空列表处理。

### 90 秒演示脚本

1. 打开应用，点批注栏顶部 **「① 一键载入演示批注」**：4 条批注中 2 条正常挂接（媒体垂询段、含单侧改稿模糊跟随的公司简介段），2 条因未解决冲突而脱离，冲突卡片顶部出现黄色脱离提示横幅。
2. 点 **「② 品牌再移动一段」**：媒体垂询段移到文首，其上批注自动跟到新位置（`段落移动后跟随`）。
3. 在行长引言冲突上点 **「采用法务版」**：原本脱离的批注自动重新挂回新正文（`冲突时脱离 → 解决后恢复`）。
4. 在免责声明冲突上点 **「采用品牌版（删除此段）」**：批注变 `待重挂`；点它的 **「手动重挂」**，在"关于星澜科技"段选中几个字并确认，批注挂到新位置。
5. 任意一步都可 `Ctrl/Cmd+Z` 撤销；刷新页面后批注与裁决仍在；点「复制合并稿」验证导出文本不含任何批注。

## 合并算法说明

1. **对齐**（每个修订版 vs 底稿）：先用 LCS 匹配内容完全一致的段落作为锚点；未匹配段落按词级相似度（Dice 系数）贪心配对——同一"空隙"内阈值较低（视为原地改写），跨空隙阈值较高（视为移动）；最后用 LIS 找出保持相对顺序的最大配对集合，集合之外的配对即为移动段落，其余未配对的分别是删除与新增。
2. **裁决**（对底稿每一段）：分别在"存在性 / 位置 / 内容"三个维度比较三方——双方都删则删；一方删、另一方动过（改或移）则冲突；移动目标唯一则采用新位置；内容按"两方一致用一致值、否则用改动方"自动合并，双方都改且不同则冲突。
3. **组装**：原地段落占据底稿槽位，移动/新增段落挂在锚点槽位之后排序输出；双方在同位置插入相同内容时去重。

## 项目结构

```
src/
  lib/
    text.ts        分词（中文按字/英文按词）、归一化、段落切分
    lcs.ts         LCS / LIS 序列算法
    similarity.ts  段落相似度
    align.ts       底稿↔修订版段落对齐（含移动识别）
    diff.ts        词级 diff（界面高亮用）
    merge.ts       三方合并、冲突分类、裁决应用、导出
    annotation.ts  批注指纹、引文定位（精确/归一化/模糊）、重挂状态机
    selection.ts   浏览器选区 → 合并稿文本坐标（跳过 diff 删除字）
    *.test.ts      合并 / 移动识别 / 人工解决 / 批注挂接 / 选区映射 测试
  state/
    history.ts     撤销/重做历史栈（纯函数）
    useWorkbench.ts 工作台状态（裁决+批注共用历史）+ localStorage 持久化
    useTextSelection.ts 正文选区监听
    history.test.ts
  components/      工具栏、统计栏、冲突侧栏、原稿栏、合并栏、冲突卡片、
                   批注侧栏、批注正文渲染（AnnotatedText / AnnotatedDiffText）等
  sample.ts        内置联合发布稿示例 + 90 秒演示批注/段落移动种子
  sample.test.ts   示例稿件端到端校验
  app.test.tsx     界面冒烟测试（解决/撤销/重做/恢复/持久化）
  annotation.test.tsx 批注端到端（添加/跟随/冲突脱离/恢复/重挂/旧数据/导出隔离）
```

## 测试

`npm test` 运行 80 个用例，覆盖：

- 三方合并基本规则（单方修改、双方同改、插入、删除、去重）
- 移动识别（单方移动、移动+他方改写、双方同位移动、移动分歧、移动 vs 删除）
- 冲突分类（edit-edit / delete-edit / delete-move / move-move）
- 人工解决（四种裁决方式、重新打开、导出标记）
- 撤销 / 重做历史栈
- 内置示例的端到端合并结果
- **批注挂接**：精确挂接、段落移动跟随、单侧改稿模糊跟随、删除/大幅重写待重挂、
  未解决冲突脱离、解决后自动恢复、重复候选歧义、前后缀消歧、手动重挂、歧义候选点选
- **选区映射**：普通文本与跨 `<del>/<ins>` 的新文本坐标、删除字不可选、跨块拦截
- **批注端到端界面**：添加/编辑/删除/重挂、90 秒演示全流程、撤销重做、
  localStorage 恢复、旧版数据兼容、复制导出不含批注
- 界面冒烟（渲染示例、解决冲突、撤销重做、恢复示例、localStorage 持久化）
